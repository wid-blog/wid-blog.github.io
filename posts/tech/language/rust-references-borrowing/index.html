Rust 참조와 borrow

2026년 10월 29일 · 약 11분 읽기
목차
  • 함수 인자
  • 공유 참조와 가변 참조
  • 지역 값을 가리키는 참조
  • 슬라이스
  • 재대여
  • 마무리

Rust 에서 &value 는 소유권을 넘기지 않고 값을 빌린다(borrow). 빌리는 동안 공유 참조 &T 는 여러 개 만들 수 있고, 가변 참조 &mut T 는 하나만 만들 수 있다. 공유 참조와 가변 참조를 같이 만들 수도 없다. 컴파일러는 이 규칙으로 읽는 쪽이 있는 동안 값이 바뀌는 코드를 거부하고, 소유자가 먼저 사라져 해제된 값을 가리키게 될 참조도 따로 검사해 거부한다.

값을 함수에 넘길 때마다 소유권을 옮겼다가 돌려받는 방식은 번거롭다고 봤다. 대부분의 함수는 값을 읽거나 고치기만 하면 되고, 그때 쓰는 것이 참조다. 참조를 쓰면 어떤 코드가 거부되고 그 이유가 무엇인지, 문자열 일부를 가리키는 슬라이스와 가변 참조를 다시 넘기는 재대여(reborrow)는 어떻게 동작하는지 정리하고 싶었다. 아래 예제는 모두 rustc 1.94.1, edition 2021 에서 컴파일했고, 컴파일되는 예제는 실행해 출력을 확인했다.

함수 인자#

매개변수 타입을 &String 으로 두면 함수는 값을 빌리기만 한다. 호출한 뒤에도 message 를 계속 쓸 수 있다.

fn char_count(text: &String) -> usize {
    text.chars().count()
}

fn main() {
    let message = String::from("héllo");
    let count = char_count(&message);
    println!("{message} has {count} chars");
}

héllo has 5 chars

char_count 가 끝나면 매개변수 text 의 스코프도 끝나지만, text 는 참조라서 문자열은 drop 되지 않는다. 문자열의 소유자는 여전히 main 의 message 다. 호출하는 쪽에도 &message 라고 적으므로, 이 호출이 값을 빌리기만 한다는 것이 호출부에서 보인다. 문자열을 읽기만 하는 함수에 더 맞는 매개변수 타입은 슬라이스 절에서 본다.

공유 참조로는 값을 고칠 수 없다. 빌린 문자열에 덧붙이려 하면 E0596 이 발생한다.

fn append_suffix(text: &String) {
    text.push_str(" world");
}

error[E0596]: cannot borrow `*text` as mutable, as it is behind a `&` reference
 --> mut_on_shared.rs:2:5
  |
2 |     text.push_str(" world");
  |     ^^^^ `text` is a `&` reference, so it cannot be borrowed as mutable
  |
help: consider changing this to be a mutable reference
  |
1 | fn append_suffix(text: &mut String) {
  |                         +++

제안대로 가변 참조 &mut String 을 받으면 소유권을 넘기지 않고 값을 고칠 수 있다. 값을 받아 고친 뒤 다시 반환하던 함수가 반환값 없이 끝난다.

fn append_suffix(text: &mut String) {
    text.push_str(" world");
}

fn main() {
    let mut message = String::from("hello");
    append_suffix(&mut message);
    println!("{message}");
}

hello world

가변 참조를 만들려면 원래 변수도 let mut 이어야 하고, 호출부에도 &mut 를 적어야 한다. 함수가 인자를 고칠 수 있는지가 시그니처와 호출부 양쪽에 드러난다.

공유 참조와 가변 참조#

컴파일러가 허용하는 조합은 그림의 위 두 경우다. 같은 값에 대해 공유 참조는 여러 개 동시에 둘 수 있고, 가변 참조는 하나만 둘 수 있다. 공유 참조와 가변 참조가 겹치면 E0502, 가변 참조가 둘이면 E0499 가 발생한다.

가변 참조 두 개를 만들어 번갈아 쓰는 코드다.

fn main() {
    let mut log = String::new();
    let writer_a = &mut log;
    let writer_b = &mut log;
    writer_a.push_str("a");
    writer_b.push_str("b");
}

error[E0499]: cannot borrow `log` as mutable more than once at a time
 --> e0499.rs:4:20
  |
3 |     let writer_a = &mut log;
  |                    -------- first mutable borrow occurs here
4 |     let writer_b = &mut log;
  |                    ^^^^^^^^ second mutable borrow occurs here
5 |     writer_a.push_str("a");
  |     -------- first borrow later used here

에러의 세 번째 표시 first borrow later used here 가 근거다. writer_a 가 5행에서 다시 쓰이므로 첫 번째 가변 대여(borrow)가 5행까지 이어지고, 4행의 두 번째 가변 대여와 겹친다. writer_a 를 다 쓴 다음 writer_b 를 만들면 컴파일된다.

fn main() {
    let mut log = String::new();
    let writer_a = &mut log;
    writer_a.push_str("a");
    let writer_b = &mut log; // writer_a 는 위 push_str 이 마지막 사용
    writer_b.push_str("b");
    println!("{log}");
}

ab

대부분의 경우 대여는 변수의 스코프가 아니라 참조가 마지막으로 쓰이는 지점에서 끝난다. 이 구간의 계산 방식과 예외는 라이프타임 글에서 다룬다.

공유 참조가 살아 있는 동안 가변 참조를 만들면 E0502 다. 벡터를 순회하면서 같은 벡터에 원소를 추가하는 코드가 대표적이다.

fn main() {
    let mut names = vec![String::from("alice"), String::from("bob")];
    for name in &names {
        if name.starts_with('a') {
            names.push(name.to_uppercase());
        }
    }
}

error[E0502]: cannot borrow `names` as mutable because it is also borrowed as immutable
 --> e0502_loop.rs:5:13
  |
3 |     for name in &names {
  |                 ------
  |                 |
  |                 immutable borrow occurs here
  |                 immutable borrow later used here
4 |         if name.starts_with('a') {
5 |             names.push(name.to_uppercase());
  |             ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ mutable borrow occurs here

for 는 반복이 끝날 때까지 &names 를 빌린다. push 는 벡터의 버퍼를 새로 할당할 수 있고, 그러면 순회 중인 iterator 와 name 이 해제된 버퍼를 가리키게 된다. 컴파일러는 이 상황을 실행하기 전에 거부한다.

규칙은 버퍼 재할당이 없는 타입에도 똑같이 적용된다. 정수를 가변으로 빌린 채 원래 변수를 읽어도 E0502 다.

fn main() {
    let mut count = 0;
    let counter = &mut count;
    println!("{count}");
    *counter += 1;
}

error[E0502]: cannot borrow `count` as immutable because it is also borrowed as mutable
 --> e0502_int.rs:4:16
  |
3 |     let counter = &mut count;
  |                   ---------- mutable borrow occurs here
4 |     println!("{count}");
  |                ^^^^^ immutable borrow occurs here
5 |     *counter += 1;
  |     ------------- mutable borrow later used here

*counter 는 참조가 가리키는 값에 접근하는 역참조다. 이 코드는 단일 스레드라 실행해도 문제가 없어 보인다. 하지만 컴파일러는 스레드가 몇 개인지 보지 않고 빌린 방식만으로 판단한다. The Rust Programming Language 는 데이터 경합(data race)의 조건을 세 가지로 적는다. 두 개 이상의 포인터가 같은 데이터에 동시에 접근하고, 그중 하나 이상이 쓰기이며, 접근을 동기화하는 장치가 없는 경우다. 일반 참조로 값을 고치려면 가변 참조가 필요하다. 가변 참조가 살아 있는 동안 다른 참조는 없다. 그래서 쓰는 포인터와 다른 포인터가 같은 값에 동시에 접근하지 못한다. 이 규칙은 단일 스레드에서 순회 중에 버퍼가 바뀌는 문제를 막고, 스레드 사이에서는 Send·Sync trait 검사와 함께 데이터 경합을 막는다. Mutex 처럼 공유 참조로 값을 고치는 내부 가변성 타입은 이 글의 범위 밖이다.

지역 값을 가리키는 참조#

공유·가변 규칙은 빌린 값이 바뀌는 경우를 막는다. 참조가 가리키는 값이 먼저 사라지는 경우는 컴파일러가 따로 검사한다. 해제된 값을 가리키는 참조를 dangling reference 라고 한다.

함수 안에서 만든 값은 함수가 끝날 때 drop 된다. 그 값을 가리키는 참조를 반환하면, 호출한 쪽은 해제된 버퍼를 가리키는 참조를 받게 된다. 컴파일러는 이런 함수를 정의 단계에서 거부한다.

fn shout(text: &str) -> &str {
    let upper = text.to_uppercase();
    &upper
}

error[E0515]: cannot return reference to local variable `upper`
 --> e0515.rs:3:5
  |
3 |     &upper
  |     ^^^^^^ returns a reference to data owned by the current function

to_uppercase 는 새 String 을 할당하고, 그 소유자는 지역 변수 upper 다. shout 가 끝나면 upper 가 drop 되어 버퍼가 해제된다. 반환 타입 &str 은 라이프타임 생략 규칙에 따라 입력 text 에서 빌린 값을 돌려준다는 뜻인데, 실제로 돌려주는 것은 함수 안에서 해제될 값의 참조다.

새로 만든 값은 소유권째 반환한다.

fn shout(text: &str) -> String {
    text.to_uppercase()
}

fn main() {
    println!("{}", shout("hi"));
}

HI

반환할 때 소유권과 참조 중 무엇을 고를지는 값의 출처로 정해진다. 입력에서 빌린 데이터의 일부를 돌려준다면 참조를 반환할 수 있다. 함수 안에서 새로 만든 값이면 소유권을 반환해야 한다. 이동하는 것은 포인터, 길이, 용량으로 된 String 값이고 힙 버퍼는 복사되지 않는다.

입력 참조가 없는 함수에서 참조를 반환하면 다른 에러가 난다. 컴파일러는 반환 참조가 빌려 올 값이 없다며 E0106 을 내고, 'static 라이프타임을 붙이는 방법과 소유한 값을 반환하는 방법을 제안한다. 'static 쪽은 흔하지 않다는 단서가 붙어 있다.

fn default_name() -> &String {
    let name = String::from("guest");
    &name
}

error[E0106]: missing lifetime specifier
 --> e0106.rs:1:22
  |
1 | fn default_name() -> &String {
  |                      ^ expected named lifetime parameter
  |

help: consider using the `'static` lifetime, but this is uncommon unless you're returning a borrowed value from a `const` or a `static`
  |

  |                       +++++++
help: instead, you are more likely to want to return an owned value

반환 참조가 어느 입력에서 왔는지를 시그니처에 적는 라이프타임 표기는 이 글의 범위 밖이다.

슬라이스#

슬라이스는 연속된 데이터의 일부를 가리키는 참조다. 문자열 슬라이스 &str 은 그림처럼 문자열 데이터 안의 시작 주소와 길이를 담는다. &String 이 String 값을 가리키는 포인터 하나인 것과 다르다. 크기를 출력해 확인했다.

fn main() {
    let line = String::from("GET /health");
    let method: &str = &line[0..3];
    println!("{method}");
    println!("same buffer: {}", method.as_ptr() == line.as_ptr());
    println!("size_of::<&String>() = {}", std::mem::size_of::<&String>());
    println!("size_of::<&str>() = {}", std::mem::size_of::<&str>());
    println!("size_of::<&[i32]>() = {}", std::mem::size_of::<&[i32]>());
}

GET
same buffer: true
size_of::<&String>() = 8
size_of::<&str>() = 16
size_of::<&[i32]>() = 16

64비트 환경에서 &String 은 8바이트, &str 과 &[i32] 는 포인터와 길이를 합한 16바이트다. method 는 line 과 같은 버퍼의 첫 바이트를 가리키고, 문자열을 복사하지 않는다.

문자열을 읽기만 하는 함수는 매개변수를 &String 대신 &str 로 두는 편이 낫다고 판단했다. String 을 가진 쪽은 &line 을 넘기고, 문자열 리터럴은 그대로 넘길 수 있다. &String 이 &str 로 바뀌는 것은 deref coercion 이다.

fn first_word(text: &str) -> &str {
    text.split(' ').next().unwrap_or(text)
}

fn main() {
    let line = String::from("GET /health");
    let method = first_word(&line);
    println!("{method}");
    println!("{}", first_word("POST /login"));
}

GET
POST

슬라이스도 참조이므로 공유·가변 규칙을 따른다. 슬라이스가 살아 있는 동안 원본 문자열을 비우면 E0502 다.

// first_word 는 위와 같다
fn main() {
    let mut line = String::from("GET /health");
    let method = first_word(&line);
    line.clear();
    println!("{method}");
}

error[E0502]: cannot borrow `line` as mutable because it is also borrowed as immutable
 --> slice_clear.rs:8:5
  |
7 |     let method = first_word(&line);
  |                             ----- immutable borrow occurs here
8 |     line.clear();
  |     ^^^^^^^^^^^^ mutable borrow occurs here
9 |     println!("{method}");
  |                ------ immutable borrow later used here

first_word 가 첫 단어의 위치를 정수로 돌려줬다면 이 코드는 컴파일되고, clear 뒤에는 의미 없는 위치가 남는다. 슬라이스로 돌려주면 원본과의 관계가 대여로 남아서 컴파일러가 확인할 수 있다.

배열과 벡터의 일부는 &[T] 로 빌린다. &[i32] 를 받는 함수는 벡터, 고정 크기 배열, 그 일부를 모두 받는다.

fn total(values: &[i32]) -> i32 {
    values.iter().sum()
}

fn main() {
    let scores = vec![10, 20, 30];
    let fixed = [1, 2, 3, 4];
    println!("{} {} {}", total(&scores), total(&fixed), total(&scores[1..]));
}

60 10 50

재대여#

공유 참조 &T 는 Copy 라서 여러 번 넘겨도 원본이 남는다. 가변 참조 &mut T 는 Copy 가 아니다. 복사되면 같은 값을 가리키는 가변 참조가 둘 생기기 때문이다. 그런데 가변 참조를 받은 함수 안에서 그 참조를 다른 함수에 두 번 넘기는 코드는 컴파일된다.

fn append_item(items: &mut Vec<i32>, value: i32) {
    items.push(value);
}

fn fill(items: &mut Vec<i32>) {
    append_item(items, 1);
    append_item(items, 2);
}

fn main() {
    let mut items = Vec::new();
    fill(&mut items);
    println!("{items:?}");
}

[1, 2]

append_item(items, 1) 은 items 를 이동하지 않는다. 매개변수 타입이 &mut Vec<i32> 로 정해져 있으면 컴파일러는 &mut *items 를 넘긴다. items 가 가리키는 벡터를 새로 가변으로 빌리는 재대여다. 재대여는 append_item 호출이 끝나면 끝나고, 그다음 줄에서 items 를 다시 쓸 수 있다. 그림 위쪽의 짧은 막대가 호출마다 생기는 재대여 구간이고, 아래쪽은 이어서 볼 제네릭 매개변수의 경우다.

매개변수가 제네릭 T 면 사정이 다르다. 컴파일러는 T 를 &mut Vec<i32> 로 추론하고 items 자체를 넘기므로, 가변 참조가 이동한다.

fn log_and_push<T: std::fmt::Debug>(target: T) {
    println!("{target:?}");
}

fn fill(items: &mut Vec<i32>) {
    log_and_push(items);
    log_and_push(items);
}

error[E0382]: use of moved value: `items`
 --> generic_move.rs:7:18
  |
5 | fn fill(items: &mut Vec<i32>) {
  |         ----- move occurs because `items` has type `&mut Vec<i32>`, which does not implement the `Copy` trait
6 |     log_and_push(items);
  |                  ----- value moved here
7 |     log_and_push(items);
  |                  ^^^^^ value used here after move
  |
help: consider creating a fresh reborrow of `items` here
  |
6 |     log_and_push(&mut *items);
  |                  ++++++

help 가 제안하는 &mut *items 가 앞에서 컴파일러가 넣어 준 재대여를 직접 적은 형태다. 타입을 적지 않은 let alias = items; 도 같은 이유로 items 를 이동하고, let alias: &mut Vec<i32> = items; 처럼 타입을 적으면 재대여가 된다. 두 경우 모두 컴파일해 확인했다.

재대여도 대여 규칙을 따른다. 재대여한 참조가 살아 있는 동안에는 원래 가변 참조로 값을 쓸 수 없다.

fn fill(items: &mut Vec<i32>) {
    let alias = &mut *items;
    items.push(2);
    alias.push(1);
}

error[E0499]: cannot borrow `*items` as mutable more than once at a time
 --> reborrow_conflict.rs:3:5
  |
2 |     let alias = &mut *items;
  |                 ----------- first mutable borrow occurs here
3 |     items.push(2);
  |     ^^^^^ second mutable borrow occurs here
4 |     alias.push(1);
  |     ----- first borrow later used here

재대여는 가변 참조를 복사하지 않고, 원래 참조를 잠시 쓸 수 없게 만든 뒤 새 가변 참조를 빌려준다. 어느 시점에도 값을 고칠 수 있는 경로는 하나다. 함수 안에서 &mut 를 다른 함수에 여러 번 넘겨도 가변 참조가 하나라는 규칙이 유지되는 이유다.

마무리#

참조는 소유권을 넘기지 않고 값을 빌린다. 공유 참조 여러 개 또는 가변 참조 하나만 허용하는 규칙이 빌린 값이 바뀌는 코드를 거부하고, 소유자보다 오래 남는 참조는 따로 거부된다. 그래서 반환값은 입력에서 빌린 참조이거나 소유한 값이 된다. 가변 참조를 여러 번 넘기는 코드는 재대여로 컴파일되지만, 그때도 값을 고칠 수 있는 경로는 하나다. 매개변수에 & 와 &mut 중 무엇을 적느냐가 함수가 값에 할 수 있는 일을 정한다.
